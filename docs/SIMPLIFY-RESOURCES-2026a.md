# 化简的栈与展开预算

用户不方便抄写长表达式，因此本轮自行构造并缩减复现，不要求用户输入长测试。

## 已复现与修复

C7 在 64 KiB 主机计算线程中，16 层嵌套 `sin` / `erf` 的独立 `_simplify` 调用崩溃。解析、构造、打印放在主线程，并启用 `LD_BIND_NOW=1` 后仍会崩溃；回溯显示反复进入 `simplify → simplify_special_core → simplify(child)`，末端在 `collect/symbolique2liste` 耗尽栈。另一个独立复现是原始构造的 512 层 `sin`：旧 `simplify` 可保留原式，但 `_simplify` 在到达该保护前的预处理就崩溃。

新实现：

- 在 `_simplify` 的程序、向量、等式分派及 `surd2pow` 之前做预算检查；内部 `simplify` 同样检查。
- 使用最多 33 个栈帧的迭代 DFS，借用 `gen` 指针，不复制表达式。最多访问 2048 个节点，启发式函数/幂嵌套最多 6 层。
- 对最多 64 层的一元函数或单元素向量链，剥去外壳、化简小叶子一次，再原样重建语法。超过预算时保留原式，不设置可能被中断遗留的全局递归计数器。
- 整数指数绝对值至少 64 且底数为复合符号表达式时，保留紧凑幂；这也覆盖分母、负幂、根式和三角函数外壳。
- 公共根指数 LCM 先除再乘，并在乘法前限制到 256，避免 SH4 的 32 位有符号乘法溢出。此项属于源码审查修复，尚无独立复现证明它是用户 TLB 的原因。

主机上，`(1+x)^1024/x` 和 `(1+x)^(-1024)` 的旧化简输出各为 233782 字符，`sqrt((x+1)^2048+1)` 为 923768 字符；新实现保留输入的短形式。`(1+sin(x))^128` 同样保持紧凑。没有引入假定为实数的占位符，因此不会据此改变复根分支。

## 验证

[完整记录](benchmarks/simplify-resources-cycle8-2026a.json)：正常绑定与 eager binding 各 66 个独立调用，分别包含普通栈和 64 KiB 栈；覆盖 6、14、15、16、24、33、64、128、256、512 层 sin/erf/向量，廉价内层代数、计算器模式恢复，以及拒绝复杂工作后继续计算。另有 34 个完整解析/求值/化简管线测试，覆盖嵌套输入和大幂。

原有嵌套根式、448 个实奇次根取样、复模式、等式约分、命名参数显示和积分外层化简回归同时通过。`simplify(integrate(3*ln(sin(2*x)),x))` 仍安全保留尚未实现的不定积分，不能算作已求解。

真实 SH4 编译器报告的单函数栈帧：preflight 472 B，浅层重建 384 B，`simplify` 340 B，`_simplify` 140 B。DFS 本身没有逐节点 C++ 递归。单帧大小不是整个调用链或运行时峰值。

## 尚存缺口

- 守住预算并不等于完全化简。比如 `(x^2+x)^2048/(x+1)^2048` 现在保留紧凑原式，尚未增加有界因式分解来消掉公共因子。
- 超过 64 层的原始链保留输入；混合深层树也可能保留整个表达式。
- 极大的整数、多个中等幂、分数幂的公共代数扩张，以及其他入口对 `normal` / `ratnormal` 的调用仍需独立审计。已开始执行的参数求值不受 `_simplify` 入口保护。
- 审查发现 `tsimplify_common` 部分内部结果尚有未检查的向量类型访问；尚未注入错误复现，不能宣称全部 TLB 路径已消除。
- 另发现四项变量 atan 之和的旧转换可在 x=0 引入 `undef`，属于独立的定义域准确性缺口，本 checkpoint 没有假称解决。

这里运行的是仓库 FXCG 化简代码加主机 Giac 依赖，不是 SH4/MMU 模拟器。这些通过记录不能替代 CG50 实机验证。
