# KhiCAS(fx-CG50)中文翻译可行性研究报告

> 研究范围:在 KhiCAS(fx-CG50 版,仓库 `giacbf/`)中增加中文支持 —— 帮助系统汉化 + 界面汉化。
> 方法:全部结论来自一手来源(本仓库源码 + WikiPrizm 逆向文档 + 开源 add-in 源码 + 官方手册),标注 `文件:行号` 或 URL;不确定处一律标 **待验证**。
> 研究日期:2026-09;仓库现状基于 `D:\GitHub\khicas-opt`(无 git,源码有 2020-11-08 版本号,`Makefile.opt` 为优化配置)。

> **勘误(2026-09,研究后复核)**:初稿称 `giacbf/khelpen.cc` "缺失"——经查证该结论有误:研究进行期间 `khelp.cc`(6259 B)与 `khelpen.cc`(6044 B)曾从工作目录消失(原因待查),随后已从 `giacbf/malherbe.ujf-grenoble.fr*tmp`(gzip 打包的完整上游源码 tar 归档)中**恢复**,两文件尺寸与最初扫描一致、内容完整。英文版帮助源实际存在,`make khicas50` 理论可构建;中文版仍建议自建 `khelpzh.cc` 以独立成版。

## 0. 可行性结论(总判断)

**总体判断:帮助系统汉化「可行且路径清晰」;界面全面汉化「可行但工作量大」。决定性障碍不是渲染,而是「翻译量 + 换行适配 + 编码处理」。**

核心事实(全部有一手来源,详见第 3 节):

1. **fx-CG50 OS 内建字库含 GB18030 中文字形**。Casio OS 提供 GB18030 字符集切换机制:
   - `EnableGB18030()`(系统调用 0x01E0)/ `DisableGB18030()`(0x01DF)切换后续文本显示系统调用的编码;
   - `ProcessPrintChars(0x03A8)`(0x1300)设置 GB18030 模式,`0x0000` 恢复拉丁模式;
   - `PrintXY` 会把字符串前两字节 `\x03\xA8` 传给 ProcessPrintChars 自动切模式。
   - 因此 **不需要自带中文字库**;KhiCAS 只需在绘制中文时开启 GB18030 模式。
   - 已有成功先例:开源 add-in **prEader**(fx-CG 系列中文 txt 阅读器)用 OS 内建字库 + GB2312/GB18030 正常显示中文(Cemetech t=19046 + prEader 源码)。
2. KhiCAS 全部屏幕文本都走 Casio OS 文本系统调用(`PrintMini`/`PrintMiniMini`/`Bdisp_MMPrint`/`os_draw_string`),**不自带任何字体**(仓库中无字体文件,见 3.2)。
3. 帮助数据链路简单:`static_help.h`(2075 条,5 语言母本)→ `mkhelp` 拆分为单语言文件 → `khelpXX.cc` 编译进主段 → `has_static_help()` 二分查找 → 目录 F5 帮助框 / `help()` 命令显示。新增"中文版"只需:翻译数据 + 新 `khelpzh.cc` + Makefile 新目标。
4. 主要技术障碍(按严重度):
   - **E1 换行**:`textGUI.cpp` 的换行是按空格分词(空格=词边界),中文无空格 → 整段视为一个"词",**超出屏宽也不换行**(见 6.2),必须为中文加字符级断行。
   - **D2 编码**:OS 只认 GB18030(拉丁模式下的多字节是 Casio 私有编码),KhiCAS 帮助母本现为 UTF-8,界面路径还有 `remove_accents()`(catalogen.cpp:545)会误伤部分 GB18030 字节,需统一处理(见 5 节)。
   - **翻译量**:2075 条命令帮助 + 界面数十处 `lang==1?法:英` 三元串(见 4 节)。
5. 附带发现:
   - 研究期间发现 `khelp.cc`/`khelpen.cc` 曾消失,已从 `malherbe` tar 备份恢复(见文件头勘误);做中文版需自建 `khelpzh.cc`。
   - `static_help.h` 实际是 **UTF-8** 编码(非 Latin-1),证据见 5.1。

## 3. B.【决定性】屏幕文本渲染与中文字形支持

### 3.1 KhiCAS 完全依赖 OS 内建字库(仓库证据)

- 唯一文本渲染函数 `text_print`(zdisplay.cc:622-666):
  - `fontsize>=18` → `PrintMini(&x,&y,s,mode,0xffffffff,0,0,c,bg,1,0)`(zdisplay.cc:655)
  - `fontsize<16` → `PrintMiniMini(&x,&y,s,mode,c,0)`(zdisplay.cc:660)
  - 其余 → `Bdisp_MMPrint(x,y,s,mode,0xffffffff,0,0,c,bg,1,0)`(zdisplay.cc:665)
- 测宽 `text_width` → `os_draw_string(...)` / `os_draw_string_small(...)`(zdisplay.cc:670-676)
- textGUI 控件 `print()` → `PrintMiniMini` / `PrintMini`(textGUI.cpp:467-472)
- `PrintMini`/`PrintMiniMini`/`os_draw_string`/`Bdisp_MMPrint` 在 giacbf 中被 17+ 个文件引用(console.cc、main.cc、zdisplay.cc、menuGUI.cpp、fileGUI.cpp 等),**全部是 OS 系统调用**,仓库内无任何字体资源文件(无 .bdf/.fnt/.pcf/.ttf,无字模数组)。

### 3.2 OS 内建字库包含哪些字符集?是否含中文?—— **含(GB18030)**

权威一手来源(WikiPrizm,逆向工程文档,由 Cemetech 社区维护):

1. **Multi-byte strings**(https://prizm.cemetech.net/OS_Information/Multi-byte_strings/ ,原始 markdown:gitlab.com/cemetech/wikiprizm/-/raw/70961e23.../content/OS_Information/Multi-byte_strings.md):
   > "Text in Chinese and related languages is supported using the Chinese standard **GB 18030** encoding. When using PrintXY the first two bytes of the provided string are passed to **ProcessPrintChars** to set the requested encoding, and reset to the default afterwards. For other display syscalls like PrintCXY, the character set must be set manually using either ProcessPrintChars or **EnableGB18030** (or **DisableGB18030** to switch back to the default latin character set). **The CJK font is wider than the default, reducing the homescreen text width from 21 to 16 characters.**"
2. **ProcessPrintChars**(https://gitlab.com/cemetech/wikiprizm/-/raw/70961e23.../content/Syscalls/ProcessPrintChars.md):
   - 系统调用 0x1300,`int ProcessPrintChars(unsigned short code);`
   - `0x0000` = 默认拉丁字符集(`PRINT_CHARSET_DEFAULT`);**`0x03A8` = GB 18030 中文(`PRINT_CHARSET_GB18030`)**。
3. **EnableGB18030 / DisableGB18030**:0x01E0 / 0x01DF,`void EnableGB18030();` / `void DisableGB18030();`,头文件 `fxcg/display.h`。
4. **Fonts**(https://prizm.cemetech.net/OS_Information/Fonts/):
   - 24px 固定宽字体(PrintXY/Print_OS)、**18px 可变宽字体(PrintMini/GetMiniGlyphPtr)**、16px 字体(Bdisp_MMPrint);
   - 18px 字体"支持绝大多数多字节字符(拉丁/希腊/俄语)";中文固件下主菜单应用名用 **18px 字体**打印中文(说明 18px 字库含 CJK 字形)。
5. **PrintMini**(https://prizm.cemetech.net/OS_Information/Syscalls/PrintMini/):0x023C;`writeflag=0` 时只更新 x(测宽),=1 才绘制 —— 与 KhiCAS `fake` 测宽用法一致(textGUI.cpp:892、467-472)。

**社区实证(非转述,可直接复现)**:
- Cemetech 帖子 t=19046(https://www.cemetech.net/forum/viewtopic.php?start=0&t=19046):默认打印函数显示中文为**空白**;用 `PrintXY(1,1,"\x3\xa8\xc4\xe3\xba\xc3!",0,0)`(`\x3\xa8` = ProcessPrintChars(0x03A8) 前缀 + GB2312 字节)→ **正常显示"你好!"**。
- prEader(https://github.com/xuhao148/prEader):已发布的中文 txt 阅读器,README 明确 "supports Chinese output natively (e.g. fx-CG20CN, fx-CG50). It makes use of ... the very syscall of the CASIOWIN OS that enables Chinese output";源码中 `PrintXY(1,1,"\x3\xa8"+GB2312字节,...)`(reader.c)。

### 3.3 自带字库兜底方案(若真机验证发现 18px 字库缺字)

若 GB18030 模式在某些 OS 版本/字号下缺字(待验证),则需自带点阵字库 + 自绘:

| 指标 | 数值 |
|---|---|
| 常用汉字 3500 个,16×16 点阵 | 32 B/字 × 3500 ≈ **112 KB**(纯 1bit);灰度 2bit 则 224 KB |
| GB2312 全集 6763 字,16×16 | ≈ **216 KB** |
| 简化 GB18030 常用 3000 字,12×12 | 18 B/字 ≈ **54 KB** |
| 预算 | 主段 2 MB(.g3a,当前 1.89 MB,余 ~100 KB 富余,见 7.2);.ac2 3 MB |

自绘需替换 zdisplay.cc `text_print` / textGUI `print()` 的绘制路径(把字模画进 VRAM 或经 `os_set_pixel`/`draw_*`),并自写测宽——**代码改动量远大于 OS 字库方案**,仅作兜底。

## 5. D. 编码问题

### 5.1 母本真实编码(修正研究假设)

- `static_help.h` 不是 Latin-1,而是 **UTF-8**:字节统计 0xC3 出现 6078 次,其中 5930 次后随 0xA0-0xBF(合法 UTF-8 双字节变音字符);"prÃ©fixÃ©" 即 UTF-8 "préfixé" 被按 Latin-1 显示的结果。
- `aspen_translate.h` 中文列同样是 UTF-8(已验证字节序列)。
- `remove_accents()`(catalogen.cpp:545-574)专门按 **UTF-8 双字节**(0xC3 + 0xA0-0xBB)剥离变音符号 → 也证明母本是 UTF-8。

### 5.2 各编码通道可行性

| 编码 | 放进母本/经 mkhelp | 经 gcc 编译为 C 字面量 | fx-CG50 OS 渲染 |
|---|---|---|---|
| **UTF-8** | 可(mkhelp 逐字节透传,mkhelp.cc:26-36) | 可(默认 -finput-charset=UTF-8,字节原样进入窄字符串) | **不可**:OS 拉丁模式不认 UTF-8,中文显示空白 |
| **GB18030/GB2312** | 可(逐字节透传) | **风险**:源文件整体是 UTF-8,混入 GB18030 字节成非法 UTF-8,gcc10+ 可能警告/报错 | **可**:需 `EnableGB18030()`/前缀 `\x3\xa8` |
| 建议方案 | 母本/拆分文件统一存 **UTF-8**(与现状一致) | 用修改后的 mkhelp 把 ≥0x80 字节转义为 `\xNN`(ASCII 纯源,编译零风险) | 运行时:UTF-8 → GB18030 转码后再绘制,或用 `\x3\xa8` 前缀 |

- **mkhelp 转义方案**:修改 `mkhelp.cc:output()`(26-36 行),对 `s[i]>=0x80` 的字节输出 `\xNN` 十六进制转义。这样 `static_helpzh.h` 是纯 ASCII C 源码,不受编译器输入/执行字符集影响,运行时字节精确还原;对其他 5 种语言文件也安全(字节不变)。
- **remove_accents 干扰**:GB18030 双字节序列可能命中 `0xC3 + 0xA0-0xBB`(catalogen.cpp:549-569)→ 被错转成 'a'-'u' 或 '?'。对策:中文版绕过 `remove_accents`(catalogen.cpp:713 处按版本条件跳过),或母本存 UTF-8、在显示前才转 GB18030。
- **OS 是否期望 Shift-JIS**:无任何公开文档说明 fx-CG 系 OS 有 Shift-JIS 模式;中文走 GB18030。日文假名是否在 GB18030 模式的字库内有字形 → **待验证**(GB18030 标准本身可编码全 Unicode,但 OS 字库字形覆盖未知)。
- **C++ locale**:`-fno-exceptions` + 无 locale 初始化,窄字符串按字节处理,宽字符串/`std::wstring` 在 fx-CG50 构建中不用于文本输出 → 中文走窄字符串字节流即可。

  - 非编辑模式按空格分词:`toksplit(src,' ',singleword,35)`(textGUI.cpp:817;实现 stringsProvider.cpp:86-104);
  - 每词用 `print(...,fake=true)`(内部 `PrintMini` writeflag=0)假绘测宽(textGUI.cpp:892);
  - 超宽(`temptextX+textX > text->width-6`)→ 换行 `textY += lineHeight+lineSpacing`(textGUI.cpp:893-899)。
- `help()` 命令字符串里的 `\n` 由控制台分行(console.cc Line 结构),`PrintMini` 本身**不解释 \n**(WikiPrizm:OS 文本系统调用把 \n 当图形字符显示)。
- 分页:仅滚动条 + 方向键,无自动分页页数概念。

### 6.2 中文全角宽度与断行

- **断行是最大适配点**:中文无空格 → 整段 howto 是一个"词";`temptextX<text->width` 不成立时根本不换行(仅整词超宽才走分支),结果绘制到屏外被裁剪。
- 适配方案(三选一,推荐 ①):
  1. 显示层按**字符**(GB18030 双字节边界)断行:在 textGUI.cpp:817 的分词处增加"按字节流切到可容纳字符数"的逻辑(需要感知 CJK 全角宽度,或用 `MB_ElementCount`(0x1163)数显示字符数);
  2. 数据层预排版:翻译时给每行插入空格(旧式做法,丑且难维护);
  3. 每行 ≤ ~20 字时强制按固定字符数硬切(简单粗暴,英文混排会切错,可接受)。
- **每行能显示多少汉字**:屏宽 384px;`PrintMini` 18px 字体英文平均 ~7-8px/字 → ~48 字符/行;中文全角 ~2 倍宽 → **约 19~24 字/行**(WikiPrizm 记载 homescreen 24px 字体 21 字符 → 中文 16 字符,按比例外推;**具体数值待真机验证**)。垂直方向:216px − 状态区 24px − 标题 24px ≈ 168px,18px 行高 → **约 8~9 行可见**,其余靠滚动。

### 12.3 关键设计决策

1. **显式 `0x01` 标记,不用启发式**。KhiCAS 已大量使用 OS 自有宽字符字形(如 `"\xE6\x9A"` 箭头、`graphicsProvider.cpp` 的 `\xE5\x42` 符号表、`\xE5\xEA/\xEB`),这些前导字节与 GB18030 重叠。若按「含高位字节就开 GB18030」判断,会把这些数学符号显示成汉字。故中文 howto 统一加 `0x01` 前缀,渲染层只对带标记的字符串切换字符集,其他字符串字节原样保留(渲染行为与英文版完全一致)。
2. **未翻译条目保留英文原字节**。生成器对未翻译 howto 及 syntax/related/examples 字段直接复制母本原始字面量,不重新编码,避免改变现有非 ASCII 字符的显示行为。
3. **中文数据存 GB18030 字节 + `\xNN` 转义**。`static_helpzh.h` 保持纯 ASCII C 源(编译器输入/执行字符集无关),运行时零转码。
4. **自包含 syscall**。`khicas_gb18030.cc` 直接经 `0x80020070` 分发器调 `EnableGB18030(0x01E0)` / `DisableGB18030(0x01DF)` / `ProcessPrintChars(0x1300)`,避免 casiolocal 中 libfxcg 快照可能缺少这些封装。
5. **`khicaszh` 是独立目标**,只链一个帮助对象(`khelpzh.o`),不影响 khicas50/khicas90 的尺寸。

### 12.4 已完成的验证(本机,无计算器)
