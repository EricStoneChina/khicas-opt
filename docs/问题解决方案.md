# KhiCAS 用户问题调研与解决方案

> 针对用户在使用 KhiCAS 1.7.0(fx-CG50)中遇到的 4 类问题,基于源码(giacbf/)分析
> 得出的结论与解决方案。每项均标注了源码证据与实施路径。

---

## 问题 1:部分代码帮助是法语

### 现状(源码证据)

- 帮助系统结构:`static_help.h`(1MB)是**多语言母本**,语言数组为
  `{法语, 英语, 西班牙语, 希腊语, 德语}`(mkhelp.cc)
- `mkhelp` 工具按语言拆分生成 `static_helpfr.h` / `static_helpen.h` 等单语言文件,
  **5 种语言的文件全部在源码包里**(各 ~400KB)
- `khelpfr.cc` → static_helpfr.h(法语),`khelpen.cc` → static_helpen.h(英语)
- GUI 语言:`console.cc` 中 `lang==1` 为法语分支;`help.h` 注明
  `language: 1=français, 2=english`
- 构建时 `khicas90`(法语)与 `khicas50`(英语)分别链接不同帮助文件

### 用户看到法语的原因

1. 若安装的是 **khicas90** 版本(法语版)→ 整个帮助都是法语,需换 khicas50
2. 1.7.0(2022 年)时代英语帮助可能不完整,部分命令 fallback 到法语
3. console.cc 中部分 UI 字符串仅法语分支(少数遗漏)

### 解决方案

| 方案 | 说明 | 工作量 |
|---|---|---|
| **A. 换用 khicas50(立即生效)** | 英文版帮助 complete;当前源码 khicas50 用 static_helpen.h | 零 |
| **B. 全面英文化 UI** | 审计 console.cc / main.cc 中 `lang==1` 法语分支,修正 lang 默认值 | 小 |
| **C. 中文帮助** | 结构上**完全可行**:桌面版 giac 的 `cmd_howto[5]` 数组支持 5 语言,只需把一种语言槽位换成中文(如替换希腊语),翻译 ~2000 条命令的 howto,重新 `mkhelp` | 大(翻译量) |

**中文实现路径(具体)**:
1. 从 `static_help.h` 提取全部命令条目(命令名 + 英语 howto 作翻译底稿)
2. 翻译为中文 → 生成 `static_helpzh.h`(格式同其他语言)
3. 修改 `mkhelp.cc` 增加 zh 输出;`khelp.cc` 的数组加中文槽位
4. KhiCAS 侧:新增 `khelpzh.cc`(复制 khelpen.cc,include static_helpzh.h),GUI 增加语言选项
5. 重新构建

⚠️ 注意:计算器屏幕窄,中文帮助显示需要换行逻辑适配(每行字数),建议先做英文 + 简要中文混合版。

## 问题 2:画图功能不好用,操作指南差

### 现状(源码证据)

`zdisplay.cc` 的 Graph2d 类**已实现**:
- `zoomx/zoomy/zoomz`(三轴缩放)、`zoom`(整体缩放)— 4059-4129 行
- `tracemode`(轨迹模式)— 4034、5326 行
- 丰富的按键交互:F1-F9 功能键、方向键、CLIP 等(7560-7618 行)
- 3D 绘图(plot3d)、曲线信息显示(curve_infos)

### 问题本质

不是缺功能,而是:
1. **交互不直观**:功能全藏在 F 功能键里,没有屏幕提示条(或提示不清晰)
2. **操作指南差**:文档说明不足,用户不知道有哪些快捷键
3. 缺少 CASIO 原版的一些交互习惯(如即时窗口设定表格、表格联动)

### 解决方案

| 方案 | 说明 |
|---|---|
| **A. 操作速查表(立即)** | 从源码按键映射整理完整操作指南(本仓库 docs/画图操作速查.md) |
| **B. 屏显提示优化** | 在 Graph2d 交互时底部绘制当前按键提示条(源码级小改) |
| **C. CASIO 风格交互** | 增加窗口设定表格入口(类似 CASIO V-Window)、十字光标坐标显示 —— 需构建测试环境验证 |

## 问题 3:AC Break 内存溢出 → 强制重启 → 需 Delete Section

### 现状(源码证据)

- 中断机制:`set_abort()` 安装 **100ms 定时器**(kglobal.cc 169-185 行),
  `check_execution_abort()` 轮询按键,AC 按下 → `ctrl_c=kbd_interrupted=interrupted=true`
- 引擎响应:计算循环检查 `interrupted`(zsolve.cc 4660 等),中断后
  `return gensizeerr(...)` **返回错误值**(非 longjmp,路径本身较安全)
- 内存:`prizm_heap` 192KB(main.cc)+ gint KMALLOC 分配器

### 崩溃根因分析(按可能性排序)

1. **异步中断竞态**:定时器在**任意时刻**(含 KMALLOC 分配中途、BFile 写 flash 中途)
   触发。中断标志虽在检查点生效,但分配器/文件系统状态可能已半更新
2. **内存耗尽路径**:中断时 `gensizeerr` 需要分配错误对象;若堆已耗尽 → 更深崩溃
3. **长期泄漏/碎片**:反复中断时,大计算中间分配的块无法回收(gensizeerr 返回但
   局部对象清理不完整),KMALLOC 池碎片化 → 后续大分配失败
4. **状态保存损坏**:崩溃若发生在 `gint_world_switch`(保存 storage)期间 →
   section 文件写坏 → 必须 Delete Section

### 解决方案

| 方案 | 说明 | 工作量 |
|---|---|---|
| **A. 关键区屏蔽中断** | 在 KMALLOC 分配器内部、BFile 写操作期间临时屏蔽 aborttimer(嵌套计数) | 中 |
| **B. 中断安全分配** | `gensizeerr` 失败时返回静态错误对象,避免中断路径再分配 | 小 |
| **C. 存储校验与自动修复** | storage 写前备份旧数据 + 校验和;启动检测损坏自动回滚 | 中 |
| **D. 堆监控预警** | 空闲内存低于阈值时提前提示保存,避免考场上突发 | 小 |
| **E. 中断点增强** | 在更多循环(尤其内存分配循环)添加检查点,让中断更早、更干净生效 | 中 |

**建议优先 A+B+C**:直接消除"中断→损坏"的竞态窗口,并从根上防止 section 损坏。

## 问题 4:ICON 与 CASIO 官方风格不一致

### 现状(实测分析)

对照 Cemetech 的 Prizm 图标设计规范(t=6211)和 Lephe 的官方风格模板(t=17770):

| 规范要求 | 当前 KhiCAS 图标 | 差距 |
|---|---|---|
| 92x64 | ✓ | — |
| 未选中 = 纯黑背景 + 抖动图案 | ✗ 白/灰背景 | **差距大** |
| 选中 = 蓝背景 + 高光 | 蓝背景 ✓ 无高光 | 部分 |
| 主体有阴影 | ✗ 全部无阴影 | 差距 |
| 主体居中留边 | ✗ 主体顶边(边距 0) | 差距 |

### 解决方案

1. 使用 **Lephe 官方风格模板**(已下载:tools/fxcg50-icon-templates-183801.zip,
   GIMP .xcf 格式)
2. 用代码生成符合规范的图标(未选中:黑底+白抖动+χ 主体+阴影;选中:蓝渐变+抖动+
   高光+主体+阴影)→ 本仓库 `tools/generate-icons.ts`
3. 替换 giacbf/khicasio.png + khicasio1.png,重新 mkg3a 打包
