# KhiCAS 优化构建方案

> 目标:在保持功能完整和 Add-in 尺寸预算内的前提下,构建**更快、更小**的 KhiCAS。
> 分析基于上游源码(`giacbf/`),提交 d4806dd。

## 现状基线(上游编译配置)

| 项 | 上游配置 | 备注 |
|---|---|---|
| 优化级别 | `-Os`(全部模块统一) | `CXXFLAGS1`(-O3)只存在于注释掉的 zdisplay 规则中,**从未启用** |
| 指令集 | `-m4a-nofpu`(SH4A 无 FPU)+ `-mb` 大端 | 软件浮点 |
| C++ | `-std=c++11 -fno-exceptions -fno-use-cxa-atexit -fno-threadsafe-statics` | 省代码/省 RAM |
| 链接 | `-static -nostdlib -Tprizm.ld -Wl,--gc-sections` | 已开 gc-sections |
| 函数/数据分段 | **未开** `-ffunction-sections -fdata-sections` | gc-sections 效果受限 |
| 尺寸预算 | .g3a(主段)2MB / .ac2(.rominram 段)3MB | z* 模块全在 3MB 段 |

**关键结构性事实**:链接脚本把 `z*.o`(纯 CAS 引擎)单独放进 `.rominram` 段(3MB-4 预算),
GUI/IO 留在 2MB 主段。这天然支持**混合优化**:计算模块加速不影响主段预算。

## 优化措施(按收益排序)

### 1. 计算模块 -O3(速度,收益最大)⭐

`-Os` 对 CAS 这类计算密集型引擎不友好;59MHz 的 SH3 上每个周期都值钱。

- `z*.cc`(40+ 个 CAS 引擎模块)、`libbf.c`(大数)、`kgausspol.cc`、`kmodpoly.cc`、
  `kezgcd.cc`、`kthreaded.cc` 等 → `-O3 -finline-functions`
- 实现:Makefile 增加 `CXXFLAGS_FAST`,模式规则 `z%.o: z%.cc` 覆盖
- 尺寸影响:z* 模块约 +20~40%,预算 3MB 充足(需链接后实测确认)
- GUI/IO(zdisplay、console、menu 等)保持 `-Os` 省主段空间

### 2. -ffunction-sections / -fdata-sections(尺寸)⭐

配合已开的 `--gc-sections`,链接器可以**丢弃从未被引用的函数/数据**。
giac 引擎有大量未使用的代码路径(平台宏裁剪后),回收空间显著。

- 风险:两个 Add-in 分开 objcopy,需验证跨段引用不被误删
  (链接时两段在同一 ELF 内,引用完整,理论上安全;构建后必须实测)
- 上游注释中曾出现该选项(被禁用),需确认禁用原因
- 收益:可能省 10~25% 总尺寸,可为主段腾出更多空间

### 3. prizm_heap 扩容(内存)⭐

`main.cpp` 定义 `prizm_heap = 192KB`。fx-CG50 有 3MB RAM @ 0x8C200000。
若链接后 .bss 仍有空间,可把 heap 提到 256~384KB → 更大规模 CAS 计算。
需查看链接 map 确认.

### 4. libbf FFT 阈值调优(速度)

`libbf.c` 已启用 FFT/NTT 乘法,`FFT_MUL_THRESHOLD = 100`(limbs)。
- 调低到 64 可加速中规模乘法(代价:FFT 开销略高)
- 需基准验证(factor(2^127-1)、1000!、大矩阵乘法)

### 5. -ffast-math 实验项(速度,有风险)

软件浮点是主要瓶颈。-ffast-math 可显著提速,但改变浮点语义。
CAS 依赖精确算术(内部用 bignum/有理数),浮点仅用于近似计算——
**不推荐全局启用**,可在纯数值模块(如绘图采样)实验。

### 6. -flto 实验项

作者注明 "does not work for 2 addins"(两段分离链接所致)。
单段版(1-addin khicas.en)可尝试。列为远期实验。

## 验证方案

- **尺寸**:链接 `--print-memory-usage` 输出 + `mkg3a` 产物大小,对比基线
- **速度**:计算器/模拟器上跑基准脚本
  - 整数:`factor(2^127-1)`、`isprime(2^521-1)`
  - 符号:`factor(x^50-1)`、`integrate(ln(x)^5,x)`
  - 矩阵:100×100 随机矩阵求逆
  - 大数:1000! 的十进制展开
- **稳定性**:基准脚本在 -O3 与 -Os 下结果必须逐位一致

## 实施路径

1. 本仓库:Makefile 优化补丁(保持上游文件可 diff)
2. `build.sh`:一键构建(Linux/WSL:拉取 casiolocal、mkg3a、libfxcg → 应用补丁 → make)
3. 基准脚本:`bench/bench.xws`(Xcas 脚本)+ 结果记录
4. 迭代:尺寸超标→调整模块集合;速度不足→扩大 -O3 范围

## 环境需求

- **Linux 或 WSL2**(sh3eb-elf 工具链为 Linux 二进制)
- 依赖:cURL、cmake、libpng-dev、zlib1g-dev(编译 mkg3a)
- 模拟器验证(可选):fx-CG Manager(Windows/Wine)或 CEmu 类方案
